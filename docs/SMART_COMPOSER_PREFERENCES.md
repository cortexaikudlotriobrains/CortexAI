# Lean composer and preferences

Ask and Compare use the direction D composer. Desktop starts with a single compact grid: Attach, text, active options, model chip, More options, Send. Text wrapping or a newline expands it to text above controls, with a 168px textarea limit. A hidden text mirror always measures against the single-line controls' width, including while expanded. At 760px and below, text, horizontally scrollable active options, and controls occupy separate rows. Mobile text uses 16px type and controls have 40px hit targets.

The Ask model chip is the sole Smart/model control. Its menu contains Smart, three recent models with exact IDs and credit tags, All models, and New chats start with. All models groups the complete enabled, selectable `/v1/model-options` catalog by provider; the prototype's short catalog is not an application filter. Plan-locked models remain visible and open the existing upgrade dialog without being selected. Picking Smart or a model changes only this chat, closes the menu and focuses the textarea. Manual picks move to the front of the recent three.

The generated offline fallback includes every selectable registry model and provider, including Gemini and Grok. It is used during loading and failed/empty options requests; the configured Ask/Compare defaults only seed initial selections and recents. A successful API response supplies the complete menu inventory, regardless of its size. Coverage compares generated IDs with the canonical runtime registry and checks all three menu views with an unavailable API and a 21-row API response.

New chats start with is a separate drill-in. Choosing Smart or a model saves the preference and returns to the main menu; it never changes either current Ask or Compare selections, including before the first message. The footer reads: “Applies to new chats. This chat keeps what you picked above.” The next new chat resolves the preference against the available catalog and server entitlements. A locked or unavailable model falls back to the plan's generated Ask default while the saved ID is retained. Compare initializes slot one from an explicit new-chat preference, otherwise from its generated Compare default, and keeps its distinct-second-slot rule. Later preference/storage updates do not rewrite the current session.

Compare uses one chip with overlapping provider logos and two short names or “3 models”. Its menu lists all models with checkbox selection and a count. Two models cannot be reduced to one; three cannot grow to four. A plan with two slots retains the third-slot upgrade flow. The menu stays open while toggling. Restored retired targets stay visible for removal, and removing a selected locked target does not open an upgrade. Compare contains neither Smart nor a new-chat preference row. Its footer reads: “Smart isn't available in Compare. Each model answers the same prompt side by side.”

More options contains only Improve prompt and Reasoning. Desktop has five descriptive reasoning rows. Mobile has Done, THIS MESSAGE, and Auto · Low · Med · High · Max segments. The context is “Applied to Smart routing”, “Applied to {model name}”, or “Applied to every compared model”. Mobile shows the selected level's description beneath Reasoning and includes the context in the footer. Unsupported levels remain disabled; selections without controllable reasoning hide the section and active reasoning chip. Auto has no active chip. Improve and explicit reasoning have removable accent-soft pills; resetting one changes only that setting. Both new-chat modes start with Auto reasoning and Improve off.

Both menus use a 78vh maximum bottom sheet at 760px and below, with a scrim, handle, safe-area padding and focus trap. Desktop popovers are clamped within the composer above it. One menu can be open at a time. Escape returns from All models or New chats start with to the main view, then closes and restores trigger focus. Done, outside pointer-down and scrim taps dismiss; closing resets the drill-in. Model choices return focus to the textarea. Focus handling yields to the upgrade dialog. Reduced motion disables menu/sheet/scrim animations, chevron transitions and Send lift. Enter sends and Shift+Enter inserts a newline, including on mobile; IME composition does not submit.

## Storage and migration

Per-user preferences remain at `localStorage["cortex.composerPrefs.v1"]`, keyed by authenticated `whoAmI.user_id`, with a separate anonymous entry. There is no preferences HTTP API or device sync. Storage events reload preferences for subsequent new chats. Malformed or inaccessible storage falls back safely; in-memory editing remains available.

- `newChatStart: 'smart' | modelId` starts as `smart`.
- `recentModels: modelId[]` contains at most three unique manual picks. Empty recents seed from the generated Ask/Compare plan defaults and available catalog.
- Legacy migration is `newChatStart = smartForNewChats === false ? (smartOffModelId ?? askDefaults[plan]) : 'smart'`. Migration is finalized only after catalog and entitlement loading, so a missing legacy model uses the actual plan. Existing explicit `newChatStart` wins. Legacy fields remain readable for one release.

Separate per-user/session `cortex.chatComposer.v1` snapshots retain Smart/model selection, Compare targets, reasoning and Improve. Older snapshots remain readable. Restored server history supplies routing/requested-model identities when no local snapshot exists. A session awaiting history hydration cannot overwrite its saved snapshot.
